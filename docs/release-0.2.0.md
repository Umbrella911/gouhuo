# 篝火 0.2.0：升级与验收

状态：实现和本地构建完成，尚未发布。对应 #26；真实安装和开黑验收待执行。

## 不兼容变化

连接协议版本从 1 升到 2，TLS exporter 标签从 `gouhuo voice udp v1` 改为
`gouhuo voice udp v2`。旧客户端连接新服务器会收到明确的版本不匹配提示。
新客户端也不能连接旧服务器。protobuf 命名空间、13 字节 UDP 头和包长度保持原样。

ChaCha20-Poly1305 nonce 改为 `session(u32 LE) || seq(u32 LE) || domain(u32 LE)`：
语音（包含 terminator）domain=0，保活 domain=1。语音、保活各自使用连续序号，
不会把保活算进音频丢帧。序号与密钥在同一个 TLS 连接对象里保存，设备切换、重试语音、
静音和 PTT 都不会重置；采样时钟也跨设备重建连续。u32 序号耗尽后停止该域发送，
界面要求退出服务器并重新加入换密钥，禁止回绕复用 nonce。重连创建新的密钥与计数器。来源 session id 在服务器同一次运行中也不回绕复用，
耗尽后拒绝新连接；重启服务端后所有 TLS 连接都会重建并更换密钥。

服务端最多接受 32 条尚未认证的连接，在启动连接线程前占位，退出或认证完成时释放。
从 accept 开始的 10 秒总截止时间覆盖 TLS、Hello、Challenge 和 Authenticate，
不因零碎数据延长。控制面用非阻塞 socket 等待系统 IO 事件，每次等待最多 100 ms
检查取消状态；不设置 SO_RCVTIMEO。语音 UDP 的收包方式没有改变。

每条连接有 64 条控制消息的有界队列；满队列时断开该连接。网络写入由该连接的 writer
执行，每次 TLS flush 有 2 秒总写入期限；关闭不获取 TLS 锁。状态提交、落盘、向队列
入队和新人快照/订阅注册按同一提交锁排序。锁里没有 socket 写入。

客户端等待 UDP 8 秒后显示端口/防火墙排查说明，不再一直显示“语音连接中”。
音频采集或播放失败会显示设备错误和恢复建议，可点“重试语音”刷新设备并重开音频。
此操作保留身份、连接密钥、序号、闭麦和逐人音量。加密序号耗尽时必须重新加入服务器。
“诊断信息”生成可选择复制的快照，包含版本、设备、闭麦、UDP、包计数和错误提示，
不包含身份私钥、语音密钥、完整邀请链接或聊天内容；没有自动上传。

## 升级顺序

1. 先备份服务器 `gouhuo-data`，客户端导出自己的身份并妥善保存。
2. 通知这次是协议不兼容升级，让所有成员准备好 0.2.0 安装包；安排短暂停服。
3. 退出旧客户端，安装 0.2.0；服务端切换到 0.2.0 后，所有人重新加入。
4. Docker 可在 `.env` 设置 `GOUHUO_VERSION=0.2.0`，然后
   `docker compose pull && docker compose up -d`。正式发布前该镜像标签尚不存在。
5. 用原邀请链接验证双向通话、角色和频道。不要删除数据卷，不要重新生成服务端证书。

SQLite 表结构、客户端身份和邀请链接格式没有变化。保留服务端证书、域名/地址和数据卷时，
旧邀请链接仍有效。回退需要客户端与服务器一起回退到 0.1.1；本版本未新增存档迁移，
仍建议保留升级前备份。切换版本会中断在线通话。
